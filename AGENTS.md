# AGENTS.md

## Project Overview

KYC Client Onboarding is a local full-stack application with four parts:

- `src/`: Java HTTP API and business logic, compiled manually with dependency jars in `src/lib/`.
- `frontend/`: Vite + React client for client, compliance officer, and admin portals.
- `data_analysis/`: FastAPI ML/XAI service and notebooks for approval predictions and dashboard plots.
- `sql/`: MySQL schema and seed data. `scripts/db/` contains database administration scripts.

Read `README.md`, `SETUP.md`, and `API_DOCUMENTATION.md` before changing setup, database, or API behavior.

## Repository Rules

- Keep changes focused on the requested behavior. Preserve existing public API shapes and local conventions.
- Do not commit credentials, generated model artifacts, database dumps, compiled output, or dependency jars unless explicitly requested.
- Treat `passwords.txt` and `old/atlas-credentials.env` as sensitive. Do not expose their contents or copy their values into source, logs, or documentation.
- Do not edit generated documentation under `javadoc/` by hand unless the task explicitly targets generated docs.
- When changing database schema or API responses, update the relevant SQL/API documentation and keep frontend consumers aligned.
- Use ASCII for new text unless the surrounding file clearly requires another character set.

## Backend Development

- Java source is under `src/`; tests are under `test/` and mirror its package structure.
- There is no Maven or Gradle build. Compile the backend from the repository root with the existing test script or from `src/` using the classpath described in `README.md`.
- Run the complete Java test suite from the repository root if asked:

  ```powershell
  powershell -ExecutionPolicy Bypass -File scripts\run-tests.ps1
  ```

- Download test dependencies once when needed:

  ```powershell
  powershell -ExecutionPolicy Bypass -File scripts\download-test-libs.ps1
  ```

- The API normally runs on port `8080`; the ML service normally runs on port `8000`.
- Keep database access in `repository/` and business rules in `service/`. Prefer constructor injection when adding testable dependencies.
- Case status and client status are separate concepts. Case statuses are `OPEN`, `PENDING`, and `CLOSED`; client statuses include `PENDING`, `ACTIVE`, `SUSPENDED`, and `REJECTED`.

## Frontend Development

- Work from `frontend/`. It uses JavaScript, React, React Router, and Vite; do not introduce TypeScript or a new framework without a clear requirement.
- Install dependencies and run scripts with `npm.cmd` in Windows PowerShell when `npm.ps1` execution is blocked and when asked:

  ```powershell
  cd frontend
  npm.cmd install
  npm.cmd run lint
  npm.cmd run build
  npm.cmd run dev
  ```

- The frontend dev server normally runs on `http://localhost:5173`.
- The Java API base URL defaults to `http://localhost:8080`; the ML service URL defaults to `http://localhost:8000`. Use `VITE_API_BASE_URL` and `VITE_ML_SERVICE_URL` for overrides.
- Authentication is currently mocked in `frontend/src/auth/AuthContext.jsx`; do not describe it as production authentication.

## ML/XAI Development

- Install Python dependencies from `data_analysis/requirements.txt` in a virtual environment.
- `data_analysis/app.py` requires the trained `kyc_model.pkl` and `kyc_train_data.pkl` artifacts generated by `analysis.ipynb`.
- Start the service from `data_analysis/` with `python app.py`.
- Keep ML-service failures non-fatal to normal Java case operations, matching the existing fire-and-forget integration.

## Database Changes

- Use the scripts in `sql/` and `scripts/db/` rather than ad-hoc schema edits.
- The bootstrap script recreates and seeds the database. Review its warnings and environment variables before running it.
- Database scripts expect MySQL credentials through environment variables or an interactive prompt. Never hard-code credentials.
- After schema changes, update repository queries, JSON builders, API documentation, and frontend rendering/filtering as applicable.

## Validation Expectations

- Run the narrowest relevant test or build after each substantive change.
- For Java service changes, run `scripts\run-tests.ps1`.
- For frontend changes, run `npm.cmd run lint` and `npm.cmd run build` from `frontend/`.
- For API contract changes, exercise the affected endpoint and update `API_DOCUMENTATION.md`.
- Report any unavailable external dependency, database, model artifact, or service explicitly instead of claiming full validation.
